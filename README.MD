# 🚕TAXI Backend API

Реализация бэкенда для сервиса заказа сопровождения и такси (аналог Яндекс.Такси).
Реализует полный цикл взаимодействия между Заказчиком (Passenger) и Исполнителем (Driver).

---

## 🛠 Технический стек и Особенности

*   **Язык:** Go (Golang) 1.22+
*   **Архитектура:** Разделение на слои `Api` -> `Storage` -> `Models`.
*   **База данных:** In-Memory Storage (спроектировано через интерфейс для горячей замены на PostgreSQL/Supabase).
*   **Роутинг:** Standard library `net/http`.
*   **Конфигурация:** Переменные окружения (`.env`).
*   **Формат ID:** UUID v4 (Google UUID).

### Ключевые функции
1.  **State Machine заказа:** Строгая валидация переходов статусов (`searching` -> `driver_assigned` -> `waiting_for_confirmation` -> `in_progress` -> `completed`).
2.  **Генерация кодов:** При прибытии водителя генерируется случайный 4-значный код подтверждения.
3.  **Динамическое ценообразование (Mock):** Цена рассчитывается на лету в зависимости от тарифа (`economy`/`comfort`) и количества выбранных услуг.
4.  **Лента заказов:** Водители могут получать список актуальных заказов со статусом `searching`.

## 🚀 Как развернуть и запустить

### 1. Предварительные требования
*   Установленный **Go** (версия 1.22 или выше).
*   **Git**.

### 2. Установка
Клонируйте репозиторий и установите зависимости:

```bash
git clone https://github.com/CloudCorn1814/taxi-backend.git
cd taxi-backend
go mod tidy
```
---
### 3. Конфигурация (.env)
Проект поддерживает настройку через переменные окружения.
Создайте файл `.env` в корне проекта (или скопируйте пример):

*Linux/macOS:*
```bash
cp .env.example .env
```
*Windows:*
Вручную создайте файл `.env` и вставьте содержимое из `.env.example`.

**Доступные параметры:**

| Переменная | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `PORT` | Порт HTTP сервера | `:8080` |
| `DATABASE_URL` | Строка подключения к PostgreSQL | *(Зарезервировано для миграции)* |

### 4. Запуск сервера
```bash
go run cmd/main.go
```
После запуска API будет доступно по адресу: `http://localhost:8080`

## 🔌 API Documentation

### 👤 Заказчик (Passenger)

| Метод | Эндпоинт | Описание |
| :--- | :--- | :--- |
| **POST** | `/api/order` | Создание заказа. Рассчитывает цену, устанавливает статус `searching`. |
| **GET** | `/api/order/{id}` | Получение полной информации о заказе и статусе. |
| **POST** | `/api/order/{id}/cancel` | Отмена заказа (если поездка еще не началась). |

### 🚗 Водитель (Driver)

| Метод | Эндпоинт | Описание |
| :--- | :--- | :--- |
| **GET** | `/api/orders/available` | Получить список всех заказов, ожидающих водителя (`searching`). |
| **POST** | `/api/driver/status` | Обновить статус и геолокацию (Header `X-Driver-ID`). |
| **POST** | `/api/order/{id}/accept` | Принять заказ (переводит в статус `driver_assigned`). |
| **POST** | `/api/order/{id}/arrived` | Сообщить о прибытии. **Возвращает код подтверждения.** |
| **POST** | `/api/order/{id}/status` | Сменить статус (`in_progress`, `completed`). |

## 💾 База данных: In-Memory vs Supabase

В текущей версии для простоты развертывания и проверки используется **In-Memory Storage** (хранение данных в оперативной памяти). Данные сбрасываются при перезапуске сервера.

### Архитектура и миграция
Проект построен на основе интерфейса `Storage`. Это позволяет изменить хранилище без переписывания бизнес-логики.

**Как подключить реальную БД (Supabase/PostgreSQL):**
1.  Реализовать структуру `PostgresStorage` в папке `internal/storage`, которая удовлетворяет интерфейсу (методы `SaveOrder`, `GetOrder` и т.д.), используя SQL-драйвер `pgx`.
2.  В `cmd/main.go` добавить логику выбора хранилища:
    ```go
    if cfg.DatabaseURL != "" {
        store = storage.NewPostgresStorage(cfg.DatabaseURL)
    } else {
        store = storage.NewMemoryStorage()
    }
    ```

## 🧪 Тестирование

Проект тестировался вручную с использованием **Postman**.

**Сценарий проверки:**
1.  **Создание:** `POST /api/order` -> Сервер возвращает `order_id` (UUID).
2.  **Поиск:** Водитель запрашивает `GET /api/orders/available` -> Видит созданный заказ.
3.  **Принятие:** Водитель отправляет `POST /api/order/{id}/accept` -> Статус меняется на `driver_assigned`.
4.  **Прибытие:** Водитель отправляет `POST /api/order/{id}/arrived` -> Сервер генерирует и возвращает 4-значный код подтверждения.
5.  **Поездка:** Последовательная смена статусов на `in_progress` и `completed`.
